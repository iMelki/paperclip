## Negative controls

The committed fixtures assert the broken input before exercising the actual
validator, HTTP route or isolated PostgreSQL database, then assert a repaired
request succeeds:

- Missing account scope: request rejected before ingestion, HTTP 400, message
  `sourceSystem, sourceAccountId and sourceEventId must be supplied together`.
- Direct database insert with a null account and populated source/event:
  PostgreSQL `23514`, constraint `cost_events_source_identity_complete_ck`.
  Completing the account identity inserts one row successfully.
- Changed cost, tokens, model, billing attribution or event time under an
  existing identity: HTTP-service status 409 and
  `Source event identity already exists with a different cost payload`.
  Replaying the original after each rejection returns the unchanged row.
- Four simultaneous identical imports: exactly one created result, one stored
  row and 25 cents in both agent and company totals.
- Failed post-commit cancellation: first call rejects with
  `Cancellation unavailable`; replay retries the hook after the database pause
  commits, with one cost row retained.

These are application/database rejection statuses inside passing test fixtures,
not claims that the Vitest command exited nonzero. The fixtures assert the
specific failure reason, not merely rejection.
